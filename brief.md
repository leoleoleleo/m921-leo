# Brief — Phare

## Pitch

Phare est une application web légère destinée aux apprentis et personnes en formation à Lausanne qui cherchent un lieu calme où travailler après leur journée. Elle permet de repérer rapidement les lieux encore ouverts et de vérifier les informations essentielles avant de s'y rendre.

## Public

Maya Morel, 18 ans, apprentie médiamaticienne à Lausanne. Elle se déplace en transports publics et utilise principalement son smartphone. Elle cherche une solution rapide, sans création de compte, pour trouver un lieu calme avec Wi-Fi et prise électrique après son stage.

## Écrans

- Écran 1 : Accueil / liste des lieux
- Écran 2 : Recherche et filtrage
- Écran 3 : Fiche détaillée d'un lieu
- Écran 4 : Action / itinéraire

## Contenu de chaque écran

### Écran 1 — Accueil / liste des lieux
- On y voit : les lieux disponibles, leur nom, leur statut ouvert/fermé, le niveau sonore, le Wi-Fi et les prises.
- On peut y faire : parcourir les lieux et accéder à la recherche ou aux filtres.
- Bouton principal : « Filtrer »

### Écran 2 — Recherche et filtrage
- On y voit : les critères permettant de réduire la liste des lieux.
- On peut y faire : rechercher un lieu par mot-clé et sélectionner les critères utiles.
- Bouton principal : « Voir les résultats »

### Écran 3 — Fiche détaillée d'un lieu
- On y voit : le nom du lieu, l'adresse, les horaires, le niveau sonore, le Wi-Fi, les prises et les informations utiles à la décision.
- On peut y faire : vérifier si le lieu correspond aux besoins de l'utilisateur.
- Bouton principal : « Itinéraire »

### Écran 4 — Action / itinéraire
- On y voit : une confirmation visuelle du lieu sélectionné et l'action permettant de poursuivre vers l'itinéraire.
- On peut y faire : lancer l'itinéraire.
- Bouton principal : « Lancer l'itinéraire »

## Ambiance visuelle

À définir lors de l'étape design. Le contenu doit rester clair, léger et orienté vers la consultation rapide des informations essentielles.

## Palette

À définir lors de l'étape design.

- Fond : à définir

- Accent : à définir
- Attention / erreur : à définir

## Interdits

- pas de Bootstrap
- pas de React
- pas de framework
- pas de compte obligatoire pour consulter les lieux
- pas de publicité
- pas d'informations essentielles cachées dans plusieurs menus
- pas de statuts « ouvert » présentés sans information suffisamment claire pour permettre la vérification

## Contraintes techniques

- Mobile First
- largeur de référence : 390 px
- HTML5 sémantique
- CSS moderne avec variables
- JavaScript natif
- accessibilité WCAG AA
- navigation au clavier
- contraste minimum de 4,5:1 pour le texte normal
